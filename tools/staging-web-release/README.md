# Exact staging release transport

Fallback transport when SSH authentication is unavailable. It preserves the existing installer security contract; it does not relax it. The application candidate is built from a clean committed tree and bundled with its immutable manifest and binding by the transport builder. Install/activate this administrator utility through the authorized WordPress connector; open Tools → SANRO staging release. No automatic apply, shell, eval, public endpoint, arbitrary path/URL/code parameter, cron, writer, payment or order operation exists.

Preflight requires exact home/site URL, canonical Hostinger document root, LiteSpeed PHP8.1+, active Studio/WooCommerce, exact existing installed tree, a verified committed prior journal/retained backup, safe private master/preview roots, all production/checkout/GC flags OFF and PHP ZIP/fsync capabilities. The POST is capability and source-specific nonce protected; it repeats the fresh checks under the same filesystem lock as the Python installer. Archive SHA, manifest SHA, inventory/per-file hashes and PHP syntax are checked before either rename. The old plugin is retained outside the document root; a durable intent journal supports recovery after a process dies between renames. Activation and stored data are preserved. Unknown trees/pending old transactions fail closed. Recovery only restores verified old bytes, never deletes the previous plugin.

This utility is staging infrastructure, not part of the shipped Studio ZIP. Deactivate after acceptance. The original CLI installer remains available; no new MCP, SSH access or credentials are added. Test: `php tests/studio-web-release-transaction.php`.
